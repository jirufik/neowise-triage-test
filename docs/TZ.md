# ТЗ: устойчивый разбор заявок

> **Коротко.** Сервер принимает только непустой текст (иначе 400), ждёт модель не дольше 300 мс и пропускает к менеджеру только ответ с допустимой темой и непустым черновиком. Всё остальное — `manual_review`: страница пишет «разберите вручную» и стирает прежний черновик. Каждое требование ниже имеет тест: юнит и API — `npm test` (Node 20+, без зависимостей), браузер — `npm run test:e2e` (Playwright).

## Требования (из README задания) и как проверяются

| № | Требование | Поведение | Тест |
|---|---|---|---|
| R1 | Ввод | тело — JSON-объект с `text`: строка, непустая после обрезки пробелов. Иначе HTTP 400 `{"status":"invalid_input"}`: битый JSON, пустое тело, не объект (`null`, массив, число), нет `text`, `text` не строка, `text` из пробелов | `test/api.test.mjs` — по случаю на каждый вид |
| R2 | Успех | модель вернула JSON-объект, `topic` ∈ {delivery, pricing, other}, `draft` — строка, непустая после обрезки → HTTP 200 `{"status":"ready","topic","draft"}`; черновик отдаётся обрезанным | api: «доставка», «цена», обычный текст |
| R3 | Сбой модели | таймаут, исключение, не JSON, не объект, чужая тема, пустой/нестроковый черновик → HTTP 200 ровно `{"status":"manual_review","topic":null,"draft":null}` | api: пять меток имитатора; `test/triage.test.mjs`: проверка ответа модели на граничных случаях |
| R4 | Таймаут 300 мс | модель получает `AbortSignal`; ответ сервера не ждёт модель дольше 300 мс даже если модель игнорирует сигнал (гонка с таймером) | api: `[timeout]` отвечает < 700 мс; unit: модель, игнорирующая сигнал |
| R5 | Имитатор не меняется | `mock-ai.mjs` побайтно как в первом коммите | `git diff main -- mock-ai.mjs` пуст (проверка в описании PR) |
| R6 | Страница: успех | тема человеческими словами (Доставка / Цены / Другое) и черновик | `test/ui.test.mjs` |
| R7 | Страница: ручной разбор | сообщение «Автоматический разбор не удался — разберите заявку вручную», черновик пуст; при новом запросе прежний результат стирается сразу, до ответа | ui: `viewFor(manual_review)` → draft ""; ручная проверка в браузере |
| R8 | Страница: прочее | 400 → «Введите текст заявки»; сеть/500/неожиданный ответ → то же сообщение о ручном разборе | ui |
| R9 | Запоздавший ответ | на экран попадает только ответ на последний запрос | ui: `latestOnly` с ответами в обратном порядке |
| R10 | Сервер не падает | неизвестный путь → 404 как было; исключение обработчика → 500 `server_error` | api |
| R11 | Журнал | причина `manual_review` пишется в stderr (`triage manual_review: <причина>`), в ответ API не попадает | unit: функция возвращает причину |

Вне объёма: лимит размера тела, авторизация, настоящая модель.

## Устройство

- `triage.mjs`: `parseInput(raw) → {ok,text}|{ok:false}`; `parseModelOutput(str) → {ok,topic,draft}|{ok:false,reason}`; `callModel(classify, text, ms) → строка | бросает timeout`.
- `app.mjs`: `createHandler({classify, timeoutMs=300, log})` — обработчик HTTP; модель подставляется в тестах.
- `server.mjs`: только запуск (`PORT`, 127.0.0.1) — как в README.
- `ui.mjs`: `viewFor(httpStatus, body) → {kind, message, topic, draft}`, `latestOnly()`; страница отдаёт его по `GET /ui.mjs`.

## Принятые трактовки

- «Пустой» = пустой после `trim()` — и для ввода, и для черновика (имитатор с `[empty-draft]` возвращает `"  "`, README считает это пустым). `​` `trim` не снимает — считается текстом.
- Тема сравнивается строго (`Delivery` → `manual_review`): API отдаёт значения из фиксированного списка. Черновик отдаётся обрезанным — это текст для человека.
- Успешный ответ собирается только из `status/topic/draft`; поля модели (в т. ч. `status`) в ответ не попадают.
- Content-Type запроса не проверяется (415 в README нет). В модель уходит исходный текст.
- Ответ отправляется в одном месте — после гонки модели с таймером; таймер снимается в `finally`; у промиса модели всегда есть обработчик отказа (синхронный throw тоже ловится).
- В журнал пишется только причина, текст заявки — нет (персональные данные).
- Известное ограничение (в PR): нет лимита размера тела.
- e2e в браузере — Playwright: `npm run test:e2e`; юнит- и API-тесты без зависимостей: `npm test` / `node --test test/*.test.mjs`.
